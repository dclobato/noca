Package profiles


    

  • 
A full package is what you import: problem.json with every
field, the statement, optional editorial, all test cases, and the validator source.

    • 

  • 
A public bundle is the contestant-facing download — statement, image,
public test cases and their explanations, and sample interactions. It carries no
problem.json and is deliberately not importable.

    •

sample_testcases




The ordinals — in the package's own numbering, strictly ascending — that become
public test cases. Everything else is secret. Explanations are shown next to
public cases, so a package that names none shows contestants no worked examples. It must be
empty for an interactive problem.



"sample_testcases": [1, 3]



    editorial




    Optional official explanation and solution guide. When present, it names the fixed
    editorial.md member and carries that member's independent SHA-256 digest. The
    editorial uses the same Markdown restrictions and 512 KiB limit as a Markdown statement.



"editorial": {
  "member": "editorial.md",
  "sha256": "…64 hex chars…",
  "release_policy": "after_ac"
}



    Missing or null means no editorial. Public bundles never include it. The digest
    is nested so older version-2 readers can ignore this additive field and safe archive member
    without rejecting the legacy top-level manifest as over-complete. An undeclared
    editorial.md is ignored with a warning for compatibility with older packages.




    release_policy says when the editorial becomes visible to participants:
    "never", "always" or "after_ac" (once the participant has
    an Accepted verdict on the problem). Absent or null means "never", so
    a package written before this property existed imports unchanged. Any other value is refused.
    {% if is_arena %}
        Arena stores it; a Contest package always writes null, because the Contest
        problem table has no equivalent column.
    {% else %}
        Contest parses it and writes it back as null: only Arena has a column to store
        it in, so the value does not survive a round trip through a Contest problem.
    {% endif %}




    sha256




    An integrity manifest over the exact bytes of every legacy payload member except
    problem.json itself. editorial.md is covered by
    editorial.sha256 instead. Written by every export; optional on import, where a package
    without one is accepted with a warning. When present it must cover exactly the package's
    legacy members and match them. A redundant editorial.md entry is accepted only
    when it matches; NOCA exports omit that entry for old-reader compatibility.

Format version and validation strategy



    Exports write format_version: 2, which states the problem's validation strategy
    explicitly in validator_type instead of leaving it to be guessed from whether a
    validator happens to be declared.



    
    
  • 
        Version 1 packages still import. A missing format_version also
        means version 1. Such a package carries no strategy, so it is read the only way it can be:
        one declaring a custom_validator is interactive, and any other is standard. A
        validator_type key in a version-1 package is ignored.
    
    • 
    
  • 
        Version 2 must be self-consistent. "standard" requires
        "custom_validator": null and no validator/ members;
        "interactive" requires a custom_validator. A package that
        contradicts itself is refused before anything is stored.
    
    • 
    
  • 
        Editorial is an additive version-2 field. Older readers ignore the unknown
        property and safe member; no new format version is required.
    
    • 
    
  • 
        "checker" is reserved and rejected. Output checker validation is
        not available in this build, so such a package is refused rather than imported as a draft.
    
    • 



Interactive problems (custom validator)



    A package may ship a custom interactive validator: put its UTF-8 source in
    validator/ and declare it in problem.json. The
    language_id must be an active judge language and is authoritative — a source file
    extension that disagrees with it is only a warning.



"custom_validator": {
  "language_id": "cpp20",
  "source_file": "validator/validator.cpp"
}


    
    
  • 
        An interactive package ships its test cases as in/NNN.in files
        only: a case has no expected output, it holds the data that parametrizes the
        validator for one round. Any out/NNN.out in the archive is ignored.
    
    • 
    
  • 
        Its public examples are the interaction/ transcripts, so
        sample_testcases must be empty.
    
    • 
    
  • 
        The imported validator is staged as a candidate and compiled asynchronously. The problem cannot
        accept submissions until it compiles successfully.
    
    • 
    
  • Full exports of an interactive problem include the validator source; public bundles never do.
    • 



Validation rules


    
    {% if is_arena %}
        
  • 
            statement.md is required and must not contain external links, images, or URLs.
            A Contest package carrying statement.pdf cannot be imported here.
        
    • 
    {% else %}
        
  • 
            Either statement.pdf or statement.md is required — import fails without one.
        
    • 
        
  • 
            statement.md must not contain external links, images, or URLs. A
            statement.pdf must be a real, unencrypted PDF with at least one readable page.
        
    • 
    {% endif %}
    
  • 
        At least one test case is required (ordinals 1–1000, up to 1000 cases), and both files must be
        present for each ordinal unless the problem is interactive.
    
    • 
    
  • 
        Test-case content must be valid UTF-8 — binary test cases are refused. Windows line endings are
        normalized to Unix ones on import.
    
    • 
    
  • 
        Optional explanation/NNN.txt (UTF-8) adds an explanation for the test case of the same
        number; shown to contestants below a public case.
    
    • 
    
  • 
        The archive is checked before anything is extracted: path traversal, absolute paths, symlinks,
        encrypted entries, duplicate members, and two files claiming the same test case are all refused.
    
    • 
    
  • 
        An optional illustration image is displayed below the statement. It must be a GIF, PNG, JPEG, or
        WEBP of at most 2 MiB and 2048 × 2048 pixels — the same rules as the manual upload on
        the problem form. When
        problem.json names an image, that file must be present in the package;
        otherwise a root-level image file is picked up automatically. image_caption is shown
        below it.
    
    • 
    {% if is_arena %}
        
  • 
            Categories are linked only when they already exist (matched by name or slug); unknown categories are dropped with a warning.
        
    • 
        
  • 
            A non-empty author is preserved. If omitted, you are recorded as both owner and author.
        
    • 
        
  • 
            statement_language records the language the statement is written in and must be
            exactly pt, en, or es. When the package omits it, the
            language is detected from the statement and you are asked to confirm it on the edit page — a
            statement too short to detect is left unset for you to pick.
        
    • 
        
  • 
            Contest-only fields (color, language_limits) are read and re-exported,
            but Arena has nowhere to store them.
        
    • 
    {% else %}
        
  • Categories are matched by name and created on the fly when they do not exist yet.
    • 
        
  • 
            Per-language limits for languages not allowed in this contest are skipped during import, and the
            skipped ones are listed for you.
        
    • 
        
  • 
            Arena-only fields (source, license, statement_language,
            hide_author_show_source) are read and re-exported, but Contest has nowhere to
            store them.
        
    • 
    {% endif %}
