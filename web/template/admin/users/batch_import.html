Valid values

{# Driven by ALL_CONTEST_ROLES so a role added to the enum is documented here without a template edit. The importer lower-cases before matching (`parse_import_role`), so the lower-cased enum values are exactly what a file may carry. #}
Field Accepted values
role {%- for role in all_contest_roles -%} {{ role.value | lower }}{{ ", " if not loop.last else "" }} {%- endfor -%}
password Optional. Strong password or leave blank.
email Optional. Must be a valid email address.
site Required for staff and team. Optional for other roles.
location Optional. Physical location within the site (max 16 chars).
allow_concurrent_login Optional. true, yes, 1 or false, no, 0. false limits the user to one session from one address once the contest starts. Leave it blank and the checkbox above decides for rows this import creates. A value written here is a statement about that user, so it also applies to a row that updates an existing one. Anything else fails that row rather than being guessed at.

If password is omitted or blank, a random password is generated and shown in the results. If the provided password does not meet the complexity requirements, it is also discarded and a new one is generated.

JSON imports also accept an object with optional contest-slug and a required users list.
